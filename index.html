GitHub — це просто історія змін твого проєкту.

Ця сторінка пояснює GitHub без жаргону: що таке репозиторій, які команди насправді потрібні і як команда працює над одним кодом, не заважаючи одне одному.

commit a3f9c1e

Основи GitHub

Перш ніж вводити команди, варто зрозуміти чотири слова, на яких тримається все інше.

Git

Програма, не сайт

Git — це інструмент, який запам'ятовує кожну версію твоїх файлів. Він працює локально на комп'ютері, навіть без інтернету.

GitHub

Сховище в хмарі

GitHub — це сайт, де зберігаються твої Git-репозиторії, щоб ти міг ділитися кодом і працювати над ним разом з іншими.

Repository

Папка проєкту

Репозиторій ("репо") — це папка проєкту разом з усією історією її змін. Кожен проєкт має свій репозиторій.

Commit

Збережена точка

Коміт — це знімок файлів у певний момент, як збереження в грі. До нього завжди можна повернутися.

Branch

Паралельна версія

Гілка ("бранч") дозволяє працювати над новою функцією окремо, не чіпаючи основний код, поки він не готовий.

Pull Request

Прохання об'єднати

Pull request — це запит "перевір мої зміни та додай їх до основного коду", який інші можуть переглянути перед злиттям.

02
commit 7e2d40b

Основні команди Git

Ці дев'ять команд покривають 90% того, що знадобиться у щоденній роботі. Натисни "copy" й спробуй у терміналі.

git init

Перетворює звичайну папку на Git-репозиторій. Виконується один раз, на самому початку проєкту.

git clone [посилання]

Копіює чужий репозиторій із GitHub собі на комп'ютер разом з усією історією.

git status

Показує, які файли змінені й ще не збережені в коміт. Найчастіша команда з усіх.

git add .

Готує всі змінені файли до коміту. Крапка означає "усе в поточній папці".

git commit -m "опис змін"

Зберігає підготовлені файли як нову точку в історії з коротким описом, що саме змінилося.

git push

Надсилає локальні коміти на GitHub, щоб інші могли їх побачити.

git pull

Завантажує й одразу застосовує найновіші зміни з GitHub у твою локальну копію.

git branch назва-гілки

Створює нову гілку для роботи над окремою функцією або виправленням.

git checkout назва-гілки

Перемикає робочу папку на іншу гілку, щоб продовжити роботу саме там.

03
commit f18a5c2

Командна робота над проєктом

Коли над кодом працює кілька людей, GitHub дає порядок дій, який запобігає хаосу та втраті чужих змін.

1

Кожен працює у своїй гілці

Перед новою задачею створюється окрема гілка, наприклад feature-login. Основна гілка main завжди лишається робочою й стабільною.

2

Зміни надсилаються на GitHub

Після серії комітів гілка публікується командою git push, і вона стає видимою для всієї команди.

3

Створюється Pull Request

Це формальний запит "додайте мої зміни до main". Він показує рівно те, що змінилося, рядок за рядком.

4

Колеги переглядають код

Учасники команди залишають коментарі просто біля потрібних рядків коду й просять пояснення або правки, якщо щось незрозуміло.

5

Гілку об'єднують у main

Після схвалення pull request зливається в основну гілку. Git автоматично поєднує зміни, а конфлікти позначає для ручного вирішення.

6

Задачі фіксуються в Issues

Баги та нові ідеї заводяться як issue — картку з описом, яку можна прив'язати до конкретного pull request.
