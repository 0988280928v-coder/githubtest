# Як ми працюємо над githubtest

Нас двоє. Щоб не заважати одне одному й не втрачати зміни, тримаємось простого правила:
**у `main` нічого не пушимо напряму — тільки через Pull Request.**

## Ролі

- **Автор змін** — створює гілку, робить коміти, відкриває Pull Request.
- **Рецензент** — другий учасник; переглядає PR, лишає коментарі, ставить апрув.

Ролі змінюються від задачі до задачі: хто робить зміну — той автор, інший — рецензент.

## Порядок роботи (крок за кроком)

### 1. Онови локальну копію

```bash
git switch main
git pull
```

### 2. Створи гілку під задачу

Назва гілки: `feature/…` для нового, `fix/…` для виправлень.

```bash
git switch -c feature/copy-button-feedback
```

### 3. Роби зміни й комітами фіксуй прогрес

```bash
git add .
git commit -m "коротко: що і навіщо змінив"
```

Коміт-меседж — українською або англійською, головне зрозуміло. Один коміт = одна логічна зміна.

### 4. Надішли гілку на GitHub

```bash
git push -u origin feature/copy-button-feedback
```

### 5. Відкрий Pull Request

Через сайт (кнопка **Compare & pull request**) або:

```bash
gh pr create --fill
```

У описі PR коротко: що зроблено, що перевірити рецензенту.

### 6. Рев'ю

Рецензент відкриває вкладку **Files changed**, лишає коментарі біля рядків.
Якщо все ок — **Approve**. Якщо потрібні правки — **Request changes**.

Автор вносить правки в ту саму гілку (`git add` → `git commit` → `git push`) — PR оновиться сам.

### 7. Мердж

Після апруву автор натискає **Squash and merge**, потім видаляє гілку кнопкою **Delete branch**.

```bash
git switch main
git pull            # підтягнути щойно змерджене
```

## Конфлікти

Якщо GitHub пише про конфлікт — оновлюємо гілку від `main` і вирішуємо локально:

```bash
git switch feature/моя-гілка
git fetch origin
git merge origin/main
# відкрити файли з <<<<<<< ======= >>>>>>>, лишити правильний варіант
git add .
git commit
git push
```

## Issues

Баги та ідеї заводимо як **Issue** (вкладка Issues → New issue). У PR пишемо `Closes #номер`,
щоб issue закрилась автоматично після мерджу.

## Домовленості про код

- Один HTML-файл, без збірки. Правимо його напряму.
- Відступи — 2 пробіли (як у наявному коді).
- Перед PR відкрий сторінку в браузері й переконайся, що нічого не зламалось.
